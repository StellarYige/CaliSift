# CaliSift 桌面使用说明

## 建立工作区与导入

填写原文中的完整姓名。工作区是本机独立日历，切换不同姓名时建立新工作区，原工作区继续保留。姓名按完整文本匹配，类似姓名不会自动替代。

选择文件或拖入窗口，也可点击“粘贴截图”。每批最多十个文件、五张图片，单文件 10 MiB、合计 30 MiB。图片需为 PNG / JPEG，解码后不超过 1200 万像素。

选择缺省年份及来源。默认追加；只有“更新已有来源”才检查旧安排是否取消，并要求明确的覆盖日期。一个导入任务归于一个逻辑来源；不同来源可分批导入。

图片可先旋转、框选裁剪。请保留姓名、日期表头和安排内容。识别期间显示真实任务状态，不用伪造的百分比表示模型进度。表格最多处理 20 秒，图片最多 90 秒；失败可重试单个文件。修改年份或规则后应重新识别整个任务。

## 核对原文和草稿

表格每页显示 50 行、20 列，能够切换工作表和翻页，全部表格区域均可访问。点击草稿定位原文。图片安排保留相关局部证据；文字分数表示 OCR 对文字的识别分数，不等于日程正确率。

在“核对识别文字”中修正姓名或文字后重新提取，系统保存相关原识别文字及修正依据。没有找到本人安排时，先检查完整姓名和表格布局，不要直接把其他人的安排改成本人。

单条修正可补日期、时间、地点和分类。只有开始时间时允许保留单点时间；全天必须明确选择。批量修正先显示影响项，未填字段保留原值。重新识别会重建当前草稿，已有日历不受影响。

确认变化预览后写入本机。预览与当时的草稿和日历版本绑定；草稿变化、其他修改或程序重启后，旧预览失效，需重新预览。

## 规则与课程

班次规则绑定来源，原表已经写明的时间优先。修改来源规则时先预览影响，再确认应用。模板可以独立导入导出；共享前逐项检查表头和说明中没有私人信息。

自动识别不足时可在工作台指定布局、表头行、姓名轴和日期轴，或明细表的事项/时间列。完整表头一致时给出模板候选，由用户选择，不静默套用。

学期规则包括第一教学周的周一、学期周数和有序节次。填写课程的星期、连续节次及周次规则，展开后核对实际日期。临时调课在“安排预览”修改单次安排，不改变整个学期。程序不根据法定节假日推断学校调课。

“模板”页支持同时录入多门课程、复制课程行、载入上次学期。已保存模板可以载入编辑、复制或删除；删除模板不会改变已有来源中保存的规则。

## 四个入口与个性化

“导入”处理文件和草稿，“来源与历史”在其第二页签；来源、年份、模板配置默认折叠。“安排”可查找、修改并导出日历；导入确认后也可直接继续导出。“模板”管理可复用规则，“设置”管理工作区、外观和备份。

已保存安排的单项编辑直接保存，失败保留编辑内容；批量修改和来源更新仍需确认预览。在设置中选择系统 / 浅色 / 深色主题、14 / 17 / 20 px 字号、舒适 / 紧凑间距、周一 / 周日起始，以及自定义分类颜色。停用分类会保留历史记录。工作 / 学习配置起点只调整模板页面的展开内容，不预设适用于所有人的班次时间。

外观设置使用独立版本，切换主题不影响正在核对的日历预览。窗口尺寸、核对面板宽度和最近工作区在当前设备记忆。

## 更新与归档

上传新版，选择原逻辑来源和覆盖范围。完全一致的记录自动对应；疑似改时间、改日期或改地点的记录需明确对应。未对应旧记录需逐条确认取消；空表、未找到姓名或解析不完整时保留旧安排。

新版与个人修正冲突时选择保留修正或采用新版。一个来源更新不会抹除另一个来源仍支持的安排。来源历史保留最近三个导入版本，支持撤销最近一次来源更新。

可隐藏或恢复安排，也可以按实际结束日期归档。跨夜安排按结束的实际日期归档，在“已归档”中查询和恢复。身份不会因归档而变化。

## ICS 导出

保存日期、来源、分类、提醒及文件名为导出方案。导出预览列出可导出项及排除原因。已确认但没有时间的安排需补全时间或明确设为全天；待确认、隐藏、归档及取消项不进入 ICS。

文件使用 Asia/Shanghai，保留稳定 UID、修订序号和来源摘要。重复导出相同内容不增加序号；改变时间、地点或提醒等有效内容会增加修订。ICS 不包含原始截图。

ICS 是静态快照。首次测试请使用专用日历。重复导入可能重复新增；新版不再包含某项，也不等于外部日历会删除该项。只有按目标客户端实际操作验证后，才能确认新增、改期、取消和提醒效果。本版本客户端验证状态见 [desktop-verification.md](desktop-verification.md)。

Thunderbird 155.0 的实际导入器测试、重复导入与改期限制见 [日历兼容性记录](calendar-compatibility.md)。

## 备份、迁移与恢复

数据目录为 `%LOCALAPPDATA%\CaliSift`。手动备份是带校验清单的 `.calisift-backup.zip`，包含当前工作区、隐藏/归档/取消记录、来源历史、个人修正、规则模板、导出状态和仍引用的图片证据。**未完成导入的原文件和模型不在手动备份中**。

macOS 使用 `~/Library/Application Support/CaliSift`。alpha.2 的备份格式为 v2，增加外观偏好与上次学期，仍接受桌面 v1 备份；设备窗口尺寸及导出文件路径不跨设备搬移。SQLite v1 首次打开时先留恢复点再事务迁移至 v2，不要用旧程序直接打开已升级数据库。

恢复先检查清单、文件哈希和引用，显示摘要。默认建立独立工作区；覆盖现有工作区需明确选择，并在覆盖前建立恢复点。失败不会清空原工作区。备份中的稳定事件 ID 继续保留；恢复到另一台电脑不会恢复旧电脑的导出文件路径。

迁移旧微信数据时，先从小程序导出 v2 JSON 备份。完整字段的 v1 快照也可导入。桌面程序不能读取手机微信的私有存储；缺失局部证据或校验失败的备份会被拒绝。

正常变更每日首次成功提交后、覆盖恢复前、安装升级前建立 SQLite 一致性恢复点，最近七份保存在 `backups/`。这些数据库恢复点仍引用同目录下的不可变 `evidence/`，因此日常迁移请使用完整 ZIP 备份。不要只搬动一个 SQLite 文件后删除证据目录。

数据库损坏无法启动时，先完整复制数据目录保留现场，再使用 `CALISIFT_DATA_DIR` 指向一个新的空目录，启动后导入最近的完整 ZIP 备份。需要人工从自动恢复点取回数据时，把恢复点复制为新目录下的 `calendar.sqlite3`，同时复制原 `evidence/`；旧目录保留到核对完成。

## 本机保存内容

导入未完成时保留暂存原文件，便于重启后继续核对。确认或丢弃后清理整份原文件。长期保存的是日程、提取依据、来源版本、个人修正及必要图片局部。导出操作只写入选择的本机文件。

没有后台推送、常驻提醒、云同步和遥测。OCR 推理不下载资源，也不调用大模型。模型损坏时在设置中选择当前版本官方离线模型包修复；校验全部通过后才启用新目录。原表解析仍可使用。

卸载默认保留用户数据。卸载 WebView2 会影响其他使用该共享运行时的软件，CaliSift 卸载器不移除它。
