# 扩展约定

- `readers.py` 提供坐标、单元格和合并区域；`parsing.parse_sheets` 是表格与 OCR 共用入口。未来 PDF 可在还原版面后接入，不在 UI 添加空入口。
- `rules.py` 管理班次、课程和模板。复杂布局扩展不能绕过姓名精确匹配、字段证据、待确认和预览。
- `calendar.py` 管理稳定身份、来源贡献、规则、变更、修正和撤销。未来云端存储需保留版本检查和修订序号，不能以内容哈希替代身份。
- `ocr.py` 的本地模型、独立进程、超时、像素上限和禁止联网是当前边界。模型升级需更新固定版本及校验值，并重新运行真实模型与独立验收集。
- `calendar.export_ics` 只生成静态文件。订阅消息和定时任务要有实际部署、权限及投递结果后才能展示启用状态。
- `calendar-store.js` 使用双快照和独立图片证据。多设备同步应先解决冲突、备份和撤销语义，再替换持久层。

完整 v0.2 的独立准确度与真机验收尚未完成，详见 [验证记录](v0.2-verification.md)。
