# 0.3.0-alpha.1 桌面验收记录

日期：2026-09-08。结论：功能实现进入 Windows 开发预览，**尚未达到 0.3.0 稳定版的全部验收门槛**。记录区分自动回归、原生交互和仍缺少的真实设备 / 数据，不能用覆盖率或合成图片推算真实照片准确率。

## 环境与复现

- Windows 11 x64，系统 build 26200；Intel Core i5-12500H，约 16 GB 内存。
- Python 3.11.9；Node.js 24；Vue 3、pywebview 6.2.1、WebView2 Evergreen。
- RapidOCR 3.4.2、ONNX Runtime 1.23.2 CPU；三个 ONNX 模型及 Noto 字体均按 `resources/models.json` 校验。
- 安装包、模型修复包和依赖源码包由仓库的固定脚本构建。当前安装包未配置代码签名；随包微软运行时及 Inno 构建工具的发布者签名已校验。

完整复现命令见 [开发文档](development.md)。原生测试使用独立临时工作区，导入的是仓库中的虚构样例，不涉及个人资料。测试把子进程 PATH 限制为 Windows System32，验证冻结程序能够独立找到 Python、模型、DLL 和字体；这**不等同于在没有开发工具的干净虚拟机上完成验收**。

## 性能记录

`scripts/benchmark_desktop.py` 生成 5000 条不冲突的已确认记录，每天一项，不包含图片证据和长修正历史。此数据量测试用于比较本机查询开销，不代表最复杂工作区。

| 操作 | 本机一次测量 |
| --- | --- |
| 创建并索引 5000 条记录 | 0.745 秒 |
| 首次查询，返回前 50 条 | 0.298 秒 |
| 再次查询 | 0.011 秒 |
| 文本筛选 | 0.015 秒 |
| 按一年日期筛选 | 0.005 秒 |
| 5000 条记录的设置变更预览 | 1.109 秒 |
| 上述 Python 进程峰值工作集 | 100.5 MiB；不含 WebView2 和 OCR 工作进程 |
| 冻结 CSV 工作进程：2 条安排 | 1.281 秒，峰值工作集 56.7 MiB |
| 冻结 OCR 工作进程：1 张合成清晰图 | 5.017 秒，峰值工作集 442.1 MiB |

原始测量：[5000 条查询](verification/desktop-performance.json)、[冻结工作进程](verification/frozen-worker-results.json)、[OCR 开发回归](verification/ocr-regression.json)。这些是构建机的一次测量，不是跨设备性能保证。界面截图：[核对工作台](images/workbench.png)、[窄窗口与大字号](images/events-narrow-large.png)。

此前首轮冻结程序启动约 10.14 秒，后续原生启动约 3–5 秒。冷启动 5 秒目标尚不能宣称全面达到；需在干净设备、不同磁盘和安全软件环境继续测量。OCR 工作进程耗时和峰值内存由 `scripts/smoke_frozen_workers.py` 另外采样，不能把它当成整套桌面程序总内存。

## 识别准确度与稳定版缺口

现有 `tests/fixtures/ocr/regression-manifest.json` 只有 **1 种布局、6 张合成变体**：清晰、旋转、轻微倾斜、压缩、合并表头、简单无边框。全部调用真实模型，本次各提取出 1 条正确记录，姓名错误关联为 0，日期 / 时间字段与人工写入的预期一致。该结果仅证明这些开发回归样例通过。

运行 `scripts.evaluate_accuracy --acceptance` 会拒绝把此集作为稳定版验收：没有 20 种独立表格布局、20 张独立图片、真实照片覆盖、独立标注复核和完整手动修正操作量。该 manifest 没有表格条目，不能从其中的 0 值推断 Excel 的实际准确率。干净表格行为另由核心测试覆盖。

| 稳定版验收项 | 当前状态 |

| 独立 20 种布局 / 20 张图片与真实拍照样本 | 未完成；公开支持声明保持清晰打印体和简单布局范围，不宣称 98% / 95% 目标已经达到 |
| 无 WebView2 的干净 Windows 离线安装 | 未完成；已随包提供并校验完整微软离线安装程序，未卸载本机共享运行时来模拟 |
